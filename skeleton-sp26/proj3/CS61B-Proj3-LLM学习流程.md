# CS61B Project 3: Percolation —— 用 LLM 学习的流程

> 核心原则：**先自己想，再问；要提示，不要答案。**

---

## 第 0 步：开场设定（1 分钟）

每次开新对话先发这段，让 LLM 进入“助教模式”：

```
我在自学 CS61B 的 Project 3: Percolation。请你当我的助教：不要直接给我完整代码或完整解法，我卡住时先给最小的提示，我明确要求时才给更多。我问概念时，用简单的例子解释。
```

---

## 第 1 步：补基础（约 30 分钟）

先看 Lecture 14（Disjoint Sets）和项目说明，再用 LLM 检查自己懂了没有。

```
请出 3 道小题测试我对并查集的理解（union、connected、find、weighted quick union 为什么快），我答完你再批改。
```

```
用一个 3×3 的例子，帮我理解渗透问题里 open、full、percolates 这三个概念的区别。
```

**过关标准**：能用自己的话说出“格子 = 元素，相邻打开 = union，有水 = 和顶部连通”。

---

## 第 2 步：自己设计（约 30 分钟）

先不写代码，自己在纸上想清楚：

- 需要哪些成员变量？
- `open` 时要做什么？
- `isFull` 怎么判断？

然后把想法发给 LLM：

```
这是我的设计思路：……（写下你的想法）。请指出有没有问题，但不要直接告诉我正确做法。
```

卡住时逐级要提示：

```
isFull 我只想到遍历整个顶行，但这样不满足性能要求。给我一个小提示。
```

---

## 第 3 步：写代码（1～2 小时）

自己写，遇到具体问题再问：

```
我的 xyTo1D 是这样写的：……，N=5 时 (2,4) 算出来不是 14，帮我看哪里错了。
```

```
这个报错是什么意思：……（贴报错信息）
```

环境配置、IntelliJ、algs4 导入这类问题，可以放心直接让 LLM 帮你解决，不影响学习。

---

## 第 4 步：攻克 backwash（看情况）

先自己用可视化工具观察 bug 现象，想 15～20 分钟。没头绪再问：

```
我看到了 backwash 的现象，但不知道原因。请先只帮我理解“为什么会发生”，不要告诉我怎么修。
```

```
我理解原因了，给我一个修复方向的提示。
```

---

## 第 5 步：测试（约 1 小时）

```
我实现完了，请列出我应该测试的边界情况，只列情况，测试代码我自己写。
```

再用可视化工具（`PercolationPicture`、`InteractivePercolationVisualizer`）对照官方输出图片（input20、heart25 等），结果一致才算对。

---

## 第 6 步：代码审查（约 15 分钟）

```
这是我的 Percolation.java：……
请帮我审查：是否满足性能要求（每个方法常数次并查集调用）、有没有遗漏的边界情况、代码风格问题。只指出问题，不要重写。
```

---

## 第 7 步：复盘巩固（约 15 分钟）

这一步最容易被跳过，但最能把知识留下来：

```
我做完了，请用 5 个问题考我这个项目的关键点（比如为什么要虚拟节点、backwash 为什么会出现、时间复杂度是多少）。
```

```
请推荐 2 道能用同样思路做的 LeetCode 题，让我练习。
```

可选：做 Task 4，让 LLM 帮你解释 quick-find 和 weighted quick-union 运行时间差异的原因。

---

## 几个提醒

- 自己想的时间不要省，这个项目真正的收获全在那里。
- 如果 LLM 不小心给了完整答案，就别照抄，关掉自己重写一遍。
- 把每次卡住的点和最终的理解简单记下来，之后复习非常有用。
