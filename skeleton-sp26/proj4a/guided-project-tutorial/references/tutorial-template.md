## 短示范：把抽象讲解改成可操作步骤

### 不推荐的写法

> 实现领域对象的数据投影接口，利用继承体系提供有序集合视图，并通过防御性复制解除外部可变性耦合。
>
> 下面是整个类的最终代码。

问题：读者不知道要修什么、改哪里、何时验证；几个术语同时出现，完整类掩盖了这一小步。

### 推荐的写法

#### 第 1 步：让年份按顺序返回

**假设已检查到的起点：** `src/main/YearData.java` 继承 `TreeMap<Integer, Double>`，`years()` 当前返回 null。以下路径和类名仅用于示范，实际教程应替换成真实项目内容。

**目标：** 先放入 2001、再放入 2000，调用 years 后仍得到 `[2000, 2001]`。

**① 在 import 区增加：**

```java
import java.util.ArrayList;
```

**② 找到 `public List<Integer> years()`，替换整个方法，不要覆盖整个文件：**

```java
public List<Integer> years() {
    return new ArrayList<>(keySet());
}
```

**这里发生了什么：**

- 父类 TreeMap 已经保存了数据，并按年份排序。
- keySet 取出这些年份。
- ArrayList 将年份复制成方法需要返回的列表。

不需要为此再声明第二个 Map，也不用现在研究 TreeMap 内部的树如何实现。

**验证：** 在已有测试类中新增一个针对 years 的测试，放入乱序年份，检查返回顺序；修改前应因返回 null 失败，修改后应通过。如果无法执行测试，就明确写“预期”，不写“已通过”。其他尚未实现方法的测试此时仍可能失败。

**想一想：** 为什么没有自己写排序，年份也能有序？

> 正式教程还要给出精确的测试文件位置、imports 和完整测试方法；本示范只展示讲解风格，不冒充完整项目教程。

## 最容易遗漏的阶段说明

- “本步尚未接到入口，重启网页不会执行它；现在只检查编译，第 N 步检查行为。”
- “当前仍是演示曲线，这是预期结果；第 N 步才换成真实数据。”
- “只运行这个测试方法，其他方法仍有 TODO，整个测试套件暂时不应全绿。”
- “这是图片编码器的现成调用，会调用即可，不要求实现编码算法。”
- “返回的是副本，修改它不应该影响下一次查询。”

这些说明要与实际项目相符，不作为任何教程的固定事实照搬。
